# Library crates that still depend on `anyhow`, accepted by
# `cargo xtask check-errors`.
#
# One crate per line: `<crate> -> <dependency>: <justification>`.
# `#` starts a comment line.
#
# The convention is in "Error handling" in docs/architecture.md: a library
# crate returns a hand-written enum, and `anyhow` belongs to `bins/`, `xtask/`
# and `crates/testing/`, where an error's last job is to be printed.
#
# This list must only shrink. The check fails on an entry whose crate no longer
# depends on `anyhow`, so remove the line in the same change that drops the
# dependency. Do not add entries to get a new `anyhow` past the gate.

# `BackendError` exists but the registry's `emit`/`link` entry points return
# `anyhow::Result` around it.
leek-backends -> anyhow: registry entry points wrap the typed BackendError

# Scenario loading (TOML + IO + validation) and the fight runner.
leek-scenario -> anyhow: scenario load/run errors not yet enumerated

# The debug adapter's handlers return `anyhow::Result` straight into the DAP
# response encoder, which only wants a message.
leek-dap -> anyhow: DAP handlers answer the protocol with a message
