# W0402: manifest key parsed but not acted on

`Miku.toml` set a key that is part of the schema — it is spelled right and
has the right type — but nothing in this toolchain reads it. The build runs
as if the key were absent.

This is distinct from `W0400` (*unknown key*), which is a typo or a key from
a newer schema. `W0402` means "we recognize what you asked for and we are
not doing it", so the message names the reason:

```
Miku.toml: `backend.native.target` is parsed but not acted on by this
           toolchain (cross-compilation is not supported; the native
           backend targets the host)
  |
5 | target = "aarch64-unknown-linux-gnu"
  | ^^^^^^
```

Silently ignoring a key like `target` is the failure this warning exists to
prevent: the build would otherwise succeed and produce a host binary while
the manifest asked for another architecture.

The fix is to delete the key, or to keep it and silence the warning once you
know it is inert:

```toml
[lint]
allow = ["W0402"]
```

Manifest warnings flow through the same severity configuration as every other
diagnostic, so `deny = ["W0402"]` turns an ignored key into a hard error
instead.

Keys that report as `W0402` today:

- `paths.benches` — benches are not run by this toolchain (see the deferred
  `[bench]` table).
- `test.parallel` — the test runner is sequential.
- `backend.jar.main_class` — the jar backend is not implemented.
- `backend.native.target` — cross-compilation is not supported.
