# E0503: edit offset is not a character boundary

A text edit produced by a rewrite pass starts or ends in the middle
of a multi-byte UTF-8 character, so the text around it cannot be cut
without corrupting that character.

Example message:

```text
error[E0503]: edit offset 7 is not a character boundary
```

Offsets that split a character mean the edit was computed against
different bytes than the ones it is applied to — the file changed
between analysis and application, or a pass did byte arithmetic on a
span instead of using the token or node range. Rather than emit
mangled text, the edit set refuses to apply.

What to do: re-run the tool so the edits are recomputed against the
current file contents. If it reproduces in a single run of one tool,
report it as a bug with the input that triggers it.

Related: E0500 (overlapping edits), E0501 (edit past end of file),
E0502 (inverted edit range).
