# W0513: migration edit skipped

`miku migrate` worked out how to rewrite a construct, but the edit
could not be applied: another rewrite of the same pass already
claimed those bytes, so the two cannot both land on one file.

```text
warning[W0513]: `subArray` → `arraySlice` rewrite could not be
                applied: edit 12..20 overlaps existing edit 10..24
  note: another rewrite of this pass already covers these bytes —
        migrate this site by hand, then re-run the migration
```

Migration is all-or-nothing per site: a rewrite made of several
edits (swapping a callback's two parameter names, renaming a callee
*and* adjusting one of its arguments) is only correct as a unit, so
when one edit is rejected the whole site is left untouched and
flagged rather than half-applied. Untouched-and-flagged compiles;
half-applied usually compiles too, and quietly means something else.

What to do: rewrite the flagged site by hand for the target version,
or simplify the surrounding expression (nested calls to migrated
builtins are the usual cause of overlapping rewrites) and run
`miku migrate` again.

See also W0510 (migrated source no longer compiles), W0511 (compiles,
but behaves differently) and W0512 (a construct the migrator refuses
to touch).
