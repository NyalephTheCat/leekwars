# W0600: unknown lint in `@allow(…)`

An `@allow(…)` annotation names something that is not a lint, so the
annotation suppresses nothing. Usually a typo, or a code from outside
the lint range — only lint findings (`L`-range codes) can be allowed.

Erroneous example:

```leekscript
// @allow(unused-varible)   <- typo: suppresses nothing
var dead = 1
```

Fix the spelling:

```leekscript
// @allow(unused-variable)
var dead = 1
```

An annotation accepts a lint's code (`L0001`), its kebab-case name
(`unused-variable`), or `all` — the catch-all for every lint finding on
the annotated statement. `miku explain L0001` prints a lint's write-up,
and the code is in every finding the linter reports.

The annotation itself may be written as `@allow(…)` or `@suppress(…)`,
optionally under a `@lint:` prefix (`@lint:allow(…)`), and a `-file`
suffix (`// @allow-file(unused-variable)`) widens it from the statement
it annotates to the whole file.

A leading annotation covers the statement below it; one trailing a
statement on the same line covers that statement:

```leekscript
var dead = 1  // @allow(unused-variable)
```
