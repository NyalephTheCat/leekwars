# E0400: manifest parse error

The project's `Miku.toml` is not valid TOML, could not be read, or could not
be found where it was expected. A manifest that parses but breaks the *schema*
gets a more specific code instead:

| code  | meaning                                                    |
|-------|------------------------------------------------------------|
| E0401 | unknown top-level key — a misspelled section                |
| E0402 | a key holds the wrong TOML type                             |
| E0403 | the right type, but a value the schema rejects              |
| E0404 | a required table or key is missing                          |
| E0405 | `[lint]` names a diagnostic code the catalog does not know  |
| W0400 | unknown key inside a known table (ignored, forward-compat)  |
| W0401 | a table that parses but whose behavior is deferred          |

Each of these points at the offending key or value in `Miku.toml`:

```text
error[E0402]: project.version must be a string
  --> Miku.toml:3:11
   |
 3 | version = 4
   |           ^
```

A minimal valid manifest looks like:

```toml
[project]
name = "my-ai"
entry = "src/main.leek"
version = "4"
```

Common causes of E0400 itself:

- TOML syntax errors — unclosed quotes, a missing `]` on a section header,
  duplicate keys;
- the file exists but cannot be read (permissions, not UTF-8);
- no `Miku.toml` in the starting directory or any parent.

Tooling falls back to standalone-file mode when no manifest is found
(e.g. `miku fmt path/to/file.leek`), but a manifest that *exists*
must parse — this error is not skippable.

The `W0400` / `W0401` warnings go through the manifest's own `[lint]` table,
so a project that knowingly carries a key this toolchain does not understand
can silence one with `allow = ["W0400"]` — or make it fatal with
`deny = ["W0400"]`.
