# W0005: block comment not closed

A `/*` block comment is still open when the end of the file is
reached. Block comments do not nest — the *first* `*/` closes the
comment — so a missing terminator makes the comment swallow every
line after it, and the code below silently stops being compiled.

Erroneous example:

```leekscript
/* disabled for now
var x = 5
return x
```

Close the comment:

```leekscript
/* disabled for now */
var x = 5
return x
```

The token is still emitted as a comment covering the rest of the
file, so the diagnostic's label points at the `/*` that opened it.
A common cause is an inner `*/` that closed an *earlier* comment
than intended: because comments do not nest, `/* a /* b */ c */`
ends at the first `*/`, leaving ` c */` as code and — if a later
`/*` follows — an unterminated comment further down.

This is a **warning**, not an error: the upstream LeekScript lexer
(`LexicalParser.tryParseComments`) accepts an unterminated block
comment silently, and two of the upstream AI fixtures end with one on
purpose — so rejecting the program would be a divergence. The warning
exists because the alternative, saying nothing at all, hides that the
rest of the file stopped being compiled.
